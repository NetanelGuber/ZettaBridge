## Task 1: registry, generator, and the 81 pointerless functions

**Files:** `third_party/registry/gl.xml` (new, committed), `tools/gen_gles.py` (new),
`core/include/zb/gl_hostcalls.h` + `core/src/gen/gl_dispatch.inc` + `core/src/gen/gl_manual.inc`
(generated, committed), `core/include/zb/gl_backend.h`, `core/include/zb/host_gl.h`,
`core/src/gl/host_gl.cpp`, `tests/host/mock_gles.{h,cpp}`, `tests/host/gles_marshal_test.cpp`,
`CMakeLists.txt`.

**Do:**
1. Download `https://raw.githubusercontent.com/KhronosGroup/OpenGL-Registry/main/xml/gl.xml`
   (2.8 MB) into `third_party/registry/gl.xml` and commit it. The build must never need the
   network. Record the download date in a one-line comment at the top of `gen_gles.py`.
2. `tools/gen_gles.py` reads that file plus `GLES2/gl2.h` from
   `$NDK/toolchains/llvm/prebuilt/linux-arm64/sysroot/usr/include`, exactly as
   `tools/gen_stubs.py` locates headers. It must assert: 142 functions in the header, 142 in
   the registry feature `GL_ES_VERSION_2_0`, and an empty symmetric difference. Exit non-zero
   on any mismatch; a registry update that changes the surface must be a loud failure.
3. Indices come from `tools/gen_stubs.py`, not from a fresh enumeration. Import its
   `gles2_names()` / `android_asset_names()` or re-derive them the same way, and fail if the
   resulting order differs from the committed `core/src/gen/hostcalls.inc`.
4. Generate direct handlers for 79 functions with no pointer parameter, plus the dispatch
   `switch`. The other two pointerless functions, `glDrawArrays` and `glGetString`, are among
   the 11 semantic handlers and must use safe manual stubs in this task. Every other index
   emits a call to a `zbgl_manual_<name>` declared in
   `gl_manual.inc`, so an unimplemented function is a **link error**, not a run-time
   surprise. Stub them in this task with a single "not implemented yet" log and a
   `GL_INVALID_OPERATION`.
5. `GlBackend` (`core/include/zb/gl_backend.h`) is one virtual function per GLES entry point,
   taking host types. Core outside `core/android/` must not include `GLES2/gl2.h`; the
   generator emits its own `GLenum`/`GLint` typedefs for the seam.
6. `HostGl` mirrors `HostJni`: constructor takes `LibraryRuntime&` and `GlBackend&`,
   `handle_host_call(index, thread)` returns false for indices above 141 (142-160 belong to
   `HostAssets`), and `GlCall` reads
   argument *n* from `r0..r3` or from `sp + 4*(n-4)`. Copy `JniCall`'s register-capture
   discipline: capture `r0-r3` **before** clearing `r0`/`r1` (this exact bug cost a debugging
   session in 4c).
7. `mock_gles` records every call and its arguments and returns predictable ids.

**Tests:** `gles_marshal_test` (new ctest): argument slots including at least one function
with more than four arguments (`glDrawElements`'s neighbours, or simply a generated call read
through a synthetic `GuestThread`), result writing for each return type, and a dispatch of
every one of the 81 pointerless functions. The mock asserts arrival for the 79 direct handlers
and `GL_INVALID_OPERATION` for the two safe semantic stubs. `gen_gles_check`
(new ctest) runs `tools/gen_gles.py --check`.

**Decisions to honour:** no 64-bit GLES 2.0 parameter exists, so argument index equals word
index everywhere; `GLintptr`/`GLsizeiptr` are one guest word widened to the host type, with
`GLintptr` sign-extended.

**Commit:** `gles: registry generator, host dispatcher, and the pointerless calls`.

## Task 2: registry-driven pointer marshaling

**Files:** `tools/gen_gles.py`, regenerated `core/src/gen/gl_dispatch.inc`,
`core/src/gl/host_gl.cpp`, `tests/host/gles_marshal_test.cpp`.

**Do:** emit marshaling for every pointer parameter that carries a `len=` and is not one of
the 11 hand-written functions. Handle the three `len=` shapes: literal (`1`..`4`), a parameter
name (`count`, `n`, `bufSize`, `size`, `maxCount`, `length`, `imageSize`) and a product
(`count*2`, `*3`, `*4`, `*9`, `*16`).

**Two traps found while prototyping this generator:**
- **A `len=` may name a parameter declared after the pointer.** `glShaderBinary`'s `binary`
  has `len="length"` and `length` is the next parameter. Read every scalar argument first,
  then the pointers.
- **The length must be computed in 64 bits** before the bounds check, or a guest `count` of
  `0xFFFFFFFF` times an element size wraps.

Guest pointers become host pointers with
`memory().host_ptr(addr, bytes, kPageRead)` for `const` parameters and
`kPageRead | kPageWrite` for outputs. **No copy:** guest memory is host memory at
`base() + addr`. A null guest address stays null and is forwarded (GLES defines null for
several of these). A non-null address that fails the check sets `GL_INVALID_VALUE` through the
backend, logs once and does **not** call the driver.

**Tests:** extend `gles_marshal_test` with one case per `len=` shape, and add
`tests/host/gles_pointer_test.cpp` with the abuse cases from the spec ("Testing"): address
past the guest space, unmapped address, read-only page as an output array, overflowing length,
absurd `glGenTextures` count, `glBufferData` larger than guest memory. Each must assert the
mock recorded **no** call and the error was set.

**Commit:** `gles: marshal pointer arguments from the registry len rules`.

## Task 3: COMPSIZE queries and pixel transfers

**Files:** `core/src/gl/gl_manual.cpp` (new), `tools/gen_gles.py`, `tests/host/gles_marshal_test.cpp`.

**Do:**
1. `gl_pname_count(GLenum pname)`: the hand table from the spec. 1 for everything except the
   2-element and 4-element queries listed there, and the two variable-length format queries,
   whose count is read first through `GL_NUM_COMPRESSED_TEXTURE_FORMATS` /
   `GL_NUM_SHADER_BINARY_FORMATS`. Unknown pname -> 1, logged once. Wire it into the generated
   handlers for `glGetBooleanv` / `glGetFloatv` / `glGetIntegerv`.
2. The nine other `COMPSIZE(pname)` functions (`glGetBufferParameteriv`,
   `glGetFramebufferAttachmentParameteriv`, `glGetProgramiv`, `glGetRenderbufferParameteriv`,
   `glGetShaderiv`, `glGetTexParameterfv`, `glGetTexParameteriv`, `glTexParameterfv`,
   `glTexParameteriv`) are 1 element in GLES 2.0. Put that in an explicit list in the
   generator, named so that an ES3 extension is a list edit.
3. `gl_pixel_bytes(format, type, width, height, alignment)`: rows are padded to the current
   `GL_UNPACK_ALIGNMENT` (or `GL_PACK_ALIGNMENT` for `glReadPixels`), the last row is not.
   Track both alignments by intercepting `glPixelStorei`. Implement
   `glTexImage2D`, `glTexSubImage2D` and `glReadPixels` with it. `glTexImage2D` with a null
   `pixels` is legal and allocates storage; forward it.
4. `glGetUniformfv` / `glGetUniformiv`: build a per-program map from uniform location to
   element count, lazily, by enumerating `glGetActiveUniform` over
   `GL_ACTIVE_UNIFORMS` and asking `glGetUniformLocation` for each name (strip a trailing
   `[0]` for arrays). Invalidate the map on `glLinkProgram` and `glDeleteProgram`. An unknown
   location writes nothing and sets `GL_INVALID_OPERATION`.

**Tests:** table-driven `gl_pixel_bytes` cases for every GLES 2.0 format/type pair at
alignments 1, 2, 4 and 8, including a 1-pixel-wide RGB texture, which is where the row padding
rule breaks naive code. `gl_pname_count` cases for a 1-, 2-, 4- and variable-length pname.
A uniform-map case in `gles_bridge_test` (Task 7) once the probe exists; here a direct unit
test against the mock is enough.

**Commit:** `gles: COMPSIZE queries, pixel sizes, and uniform read-back`.

## Task 4: strings, glGetString, and glShaderSource

**Files:** `core/src/gl/gl_manual.cpp`, `core/src/gl/host_gl.cpp`.

**Do:**
1. A bounded guest string reader: scan from `base() + addr` to a NUL, refusing to cross an
   unmapped page and refusing to exceed a fixed cap (use the JNI bridge's 64 MiB cap for
   consistency). Use it for `glBindAttribLocation`, `glGetAttribLocation` and
   `glGetUniformLocation`. An unterminated string sets `GL_INVALID_VALUE` and calls nothing.
2. `glGetString`: the driver returns a host pointer. Copy the string into guest memory once
   per enum, through the `LibraryRuntime` service `malloc`, cache it for the process, and
   return the guest address. The same enum must return the same guest pointer every time,
   because guests compare and cache these.
3. `glShaderSource`: `string` is an array of `count` **32-bit** guest pointers. Read them,
   translate each, build a host `const GLchar*[]`, and pass the guest `length` array through
   unchanged (it is `const GLint*`, same layout on both sides) or null. When `length` is null
   each string is NUL-terminated and is read with the bounded reader; when it is present a
   negative entry means NUL-terminated too. This is one of only two functions in GLES 2.0 that
   genuinely needs a copy, because the pointer width differs.

**Tests:** in `gles_marshal_test`: several sources with and without `length`, a negative
`length` entry, an embedded NUL with an explicit length, `count == 0`, a guest pointer array
that is partly unreadable (nothing is called), and `glGetString` returning a stable guest
pointer across two calls with the string readable from guest memory.

**Commit:** `gles: name lookups, glGetString caching, and glShaderSource`.

## Task 5: client-side vertex arrays and the draw calls

**Files:** `core/src/gl/gl_client_arrays.cpp` (new), `core/src/gl/gl_manual.cpp`,
`tests/host/gles_client_arrays_test.cpp` (new).

**Do:** implement the state and rules from the spec's "Client-side vertex arrays":
`glVertexAttribPointer`, `glEnableVertexAttribArray`, `glDisableVertexAttribArray`,
`glBindBuffer` tracking for `GL_ARRAY_BUFFER` and `GL_ELEMENT_ARRAY_BUFFER`, `glDrawArrays`,
`glDrawElements` and `glGetVertexAttribPointerv`.

- With a non-zero `GL_ARRAY_BUFFER` binding, `pointer` is an offset: forward the call as is.
- With binding 0, record and do **not** forward; re-issue at draw time with
  `base() + guest_pointer` after bounds-checking the byte range.
- Effective stride is `size * sizeof(type)` when `stride == 0`.
- `glDrawElements` reads the indices to find the maximum index when `indices` is a client
  pointer; with an element buffer bound it cannot, so apply the fallback from the spec's
  "Limits" and log once.
- `glGetVertexAttribPointerv` returns the recorded **guest** pointer. Returning a host pointer
  here is the single most dangerous bug available in this phase.

State lives in a `thread_local` block. A second host thread issuing GL calls logs once.

**Tests:** `gles_client_arrays_test` covers, against the mock: non-zero `first`, stride 0,
stride larger than the element, several enabled attributes, one buffer-backed attribute
alongside a client one, `GL_UNSIGNED_BYTE` and `GL_UNSIGNED_SHORT` client indices, an index
that points outside the mapped array (the draw is dropped, no call recorded), and
`glGetVertexAttribPointerv` round-tripping the guest address.

**Commit:** `gles: client-side vertex arrays and draw-time materialization`.

## Deferred to a later phase

- Batching, state caching, and any call-buffer streaming. Phase 5 is one driver call per guest
  call by decision.
- GLES 3.x, extension entry points and `eglGetProcAddress`.
- More than one GL thread per process.
- Audio and input (Phase 6).

## Open risks

- **`GLThread` and the EGL context.** The whole threading design rests on the guest's GL calls
  arriving on the host thread that borrowed the carrier of `GLThread`. That has never been
  observed with GL calls, only with JNI. If it is wrong, every GL call fails on the device and
  nothing fails here. Check it first in Task 9.
- **Client arrays with an element buffer** cannot be bounds-checked exactly. A guest that uses
  both gets the conservative path, which can still read guest memory the guest did not intend
  to expose - but never host memory outside the reservation.
- **`glGetString(GL_EXTENSIONS)`** can be several kilobytes and is allocated in guest memory
  for the life of the process. That is fine once; a guest calling it per frame would leak
  nothing, because the cache is per enum.
- **Driver strictness.** Some drivers dislike unaligned vertex pointers. Guest arrays are
  aligned as the guest compiler allocated them, so this should not arise, but a driver that
  rejects the pointer will show as a blank draw with no GL error.
- **Per-call cost.** One Dynarmic halt plus one driver call. Unmeasured. The intro screen of a
  2D game is a few dozen calls a frame; a 3D title is thousands.
