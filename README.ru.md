# ZettaBridge

**Запуск 32-битных Android-приложений на телефонах, где 32-битных процессоров больше нет.**
Открытый транслятор нативного кода ARM32 -> ARM64 и лаунчер приложений.

[Read in English](README.md)

---

## Зачем это нужно

Всё больше новых мобильных процессоров вообще не умеют исполнять 32-битный код: у них нет
режима AArch32. Пример — Snapdragon 8 Elite. Старые приложения и игры, в которых
нативные библиотеки есть только под `armeabi` / `armeabi-v7a`, на таких телефонах просто
не запускаются, и никакого аппаратного запасного пути нет.

Существующие решения либо закрыты и встроены в прошивку конкретного производителя
(Tango у Xiaomi), либо рассчитаны на другую задачу: Houdini и ndk_translation запускают
ARM-приложения на x86-устройствах.

ZettaBridge запускает такое приложение **внутри себя, в отдельном процессе**:
- Java/Kotlin-часть приложения выполняется на обычной 64-битной ART телефона;
- транслируется только 32-битный нативный код, в AArch64.

Без root, без кастомной прошивки, без изменения системы.

> **Статус: ранняя разработка.** Для обычных пользователей пока не готово. См. [дорожную карту](#дорожная-карта).

## Как это работает

```
Лаунчер ZettaBridge (arm64-приложение)
 |
 +-- импорт APK как плагина, ярлык на рабочем столе (ничего не устанавливается)
 +-- процесс :guest
      +-- Java-код плагина на настоящей 64-битной ART
      +-- libzbridge.so (arm64)
           +-- Dynarmic: JIT A32/T32 -> AArch64, 4 ГиБ гостевого адресного пространства
           +-- слой системных вызовов: 32-битный Linux ABI -> 64-битное ядро
           +-- гостевые потоки, сигналы, "carrier"-потоки для вызовов из Java
           +-- JNI-мост: синтезированный 32-битный JNIEnv / JavaVM
      +-- настоящие arm32 системные библиотеки Android (linker, libc, libm, libc++, ...)
```

- **Трансляция кода — [Dynarmic](https://github.com/Vita3K/dynarmic)** (0BSD).
  Это динамический рекомпилятор ARM, к нему приложен небольшой патч для инструкций
  Thumb-2 из ARMv8.
- **В госте работает настоящий 32-битный bionic.** Linker, libc и остальное берутся из
  образа AOSP. ZettaBridge переводит системные вызовы Linux, а не функции libc, поэтому
  совместимость с поведением Android максимальная.
- **Java и нативный код связаны через JNI-мост.**
  - `System.loadLibrary` для 32-битной библиотеки на самом деле загружает крошечный
    arm64-прокси.
  - Прокси привязывает экспорты `Java_*` гостя и вызывает его `JNI_OnLoad`.
  - Нативный код гостя видит свой 32-битный `JNIEnv`.
- **Старые библиотеки чинятся при импорте.** Текстовые релокации и абсолютные пути в
  `DT_NEEDED` переписываются, потому что современный linker Android их отвергает.

## Что уже работает

- **Ядро транслятора.** На aarch64 Linux через `zbrun`, а на настоящем телефоне — и в
  Termux, и внутри процесса приложения рядом с ART:
  - статические и динамические arm32-программы Android через настоящий 32-битный linker;
  - потоки, сигналы, C++-исключения, `dlopen`, kuser helpers.
- **Лаунчер.** Импортирует APK как плагины с ярлыками на рабочем столе. 64-битные
  приложения уже запускаются как плагины, включая приложения с Firebase/AdMob, Jetpack
  Compose и Flutter.
- **JNI-мост.** Реализован и протестирован с mock-JVM:
  - гостевые `JNIEnv`/`JavaVM`;
  - вызовы Java -> нативный код гостя из нескольких Java-потоков;
  - `RegisterNatives`;
  - загрузка библиотек и привязка `Java_*`.
- **Первая тестовая игра.** Все нативные библиотеки Orange Roulette (Haxe/OpenFL, 2014)
  загружаются вместе с точками входа JNI.

В работе: подключение JNI-моста к лаунчеру на реальном телефоне.

## Честные ограничения

- **Скорость.** Транслированный код медленнее нативного: на Snapdragon 8 Elite примерно
  в 2 раза на целочисленных вычислениях, в 3,5 раза на копировании памяти и сильнее на
  плавающей точке.
- **3D-игры сложнее, но не под запретом.** Каждый вызов из приложения в систему, особенно
  вызовы OpenGL ES, пересекает границу трансляции, поэтому тяжёлые 3D-игры поначалу будут
  медленными. Сделать их играбельными — цель проекта. В планах:
  - пакетная передача вызовов GL;
  - ускорение плавающей точки;
  - быстрые пути JNI на стороне хоста.
- **Приложения, которым нужна настоящая установка, вне рамок проекта:** собственный UID и
  разрешения, видимость для других приложений, аккаунты, push-уведомления.
- **Некоторые приложения намеренно отказываются работать внутри другого приложения**
  (Play Integrity, защита от клонирования). Такие защиты не обходятся.

## Сборка (для разработки)

Нужны:
- aarch64 Linux, clang, CMake, Ninja;
- заголовки Boost;
- Android NDK r29.

```
git submodule update --init; git -C third_party/dynarmic apply ../patches/dynarmic-0001-thumb32-armv8.patch ../patches/dynarmic-0002-asimd-narrowing.patch
```
```
cmake -S . -B build/host -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++; ninja -C build/host
```
```
tools/extract_sysroot.sh; tools/build_guest.sh; ctest --test-dir build/host; tools/run_guest_tests.sh
```

`tools/extract_sysroot.sh` скачивает образ AOSP GSI (около 1,2 ГБ) и извлекает из него
32-битные системные библиотеки в `sysroot/`. Сборка `libzbridge.so` под Android и
лаунчера описана в `CLAUDE.md` и `docs/`.
